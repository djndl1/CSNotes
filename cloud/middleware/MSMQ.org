* Features

- *distributed/federated*: every server hosts the queue infrastructure, and outgoing messages are sent locally before being delivered to their ultimate address.

- *transactional* messages: messages can be included in an atomic transaction. Transactional
  messages are exactly-once and delivered in order while non-transactional messages cannot

- *recoverability*: messages *can* be stored locally on the sending or forwarding computers until the
  message is received.
  + the opposite is non-recoverable *express* messages, stored in volatile memory.

- *direct routing* or *store-and-forward routing* (directory service required) 

- *multicast* (3.0):  distribution lists, multiple-element format names and multicast address.

- *authentication*: messages can be digitally signed.

- *encryption*: messages can be encrypted.

- *online* or *offline*: the messages can be sent even the network or the target is offline.

- *local* or *remote* read: remote messages on remote hosts' queues can be read.

* Concepts

** Queues

Logical containers used to store and later forward messages.

Queues can be created, located, opened, send and receive messages, read from. Their properties
and security descriptors can be set and retrieved.

Queues can be 

- *application queues*: created by an application or an MQ administrator
  - destination queues: store messages sent from an application
    + *public*: registered permanently in the directory service to located by other applications.
    + *private*: registered on the local computer (=%windir/system32/MSMQ/Storage/Lqs=) and their properties cannot be obtained by remote
    applications. Still integrated into the AD to deal with security and name resolution.
      + operable even if the directory service is offline
    + *transaction*: only transactional queues can accept messages sent in the context of a transaction
      - When receiving messages, only local transactional queues can be accessed within the context of a transaction.
        The transactional queue must be local to the receiving application.
        On the other hand, non-transactional queues can be accessed within or outside of a transaction.
        Also, transactional queues, local or remote, can be accessed outside of a transaction.
  - *administration queues*: used to store system-generated negative and positive acknowledgement
    messages to indicate whether these messages arrived at the destination or retrieved. The sender
    can specify a queue as an administration queue for acknowledgement.
    + any non-transactional queue is eligible.
  - *response queues*: for application-generated response messages. The sender must specify the response queues.
    + Any available queue can be used as a response queue. 
  - *report queues*: used to store report messages generated by Message Queuing or connector applications 
    when *route tracking* is enabled on the source computer by the administrator and tracing is requested for messages by the sender.
    + an auditing mechanism
    + fixed label of =MQReport Queue= and queue type identifier ={55EE8F32-CCE9-11CF-B108-0020AFD61CE9}=
  - *subqueue*: logical partitions of a physical queue. 
    + moving queues between physical queues is resource-intensive. Subqueues work as an optimized
      solution.
    + Messages cannot be sent to a subqueue. Messages can be received from subqueues,
      moved between the main queue and its subqueue, or moved between a pair of sibling subqueues.

- *system-generated queues*: generated by the MQ manager itself. Read-only by applications
  + *journal queues*: copies of all messages removed from a queue
    - queue journals =QueueReference;JOURNAL=: used to store copies of all messages with target journalling enabled removed from an application queue
    - computer journal =ComputerName;eanbledJOURNAL= or =ComputerReference\System$;JOURNAL=: stores copies of messages successfully sent from the computer
      (=positive_source journaling= enabled)
  + *dead-letter queues* =ComputerReference;DEADLETTER=, =ComputerReference:DEADXACT=: stores messages that could not be delivered (time-to-reach,
    time-to-receive timers). (negative source journaling
    enabled)
  + *connector queues*: a queue on a Connector Server (a MQ bridge) used to temporarily store messages for a
    non-MSMQ messaging system

*** Queue References

- Path name:
  + full capability
  + =ComputerName\[Private$\]QueueName= (=ComputerName= can be =.=)
  + queue names (124 Unicode characters), host names (256 Unicode characters) all have limited length

- format name: not a stored queue property but a unique name generated by MSMQ when the queue is
  created or by an application (when creating, locating, from an ADs path, a queue handle).
  + not used for creating a queue
  + public: ~PUBLIC=QueueGUID~. Location independent, used with the directory service. 
    MSMQ uses a routing algorithm to define the route to the destination queue.
  + private: ~PRIVATE=ComputerGUID\QueueNumber~
    - also location independence. AD is still required, not usable on computers operating in workgroup mode.
  + direct: reference public or private queues without the directory service, including direct
    sending, over the internet, across forest boundaries, any queue in domain, workgroup or offline
    mode.
    #+begin_src
    DIRECT=AddressSpecification\QueueName  (For public queues)  
    DIRECT=AddressSpecification\PRIVATE$\QueueName  (For private queues)  
    DIRECT=AddressSpecification\QueueName;JOURNAL  (For public queue journals)  
    DIRECT=AddressSpecification\PRIVATE$\QueueName;JOURNAL  (For private queue journals)  
    DIRECT=AddressSpecification\SYSTEM$;computersystemqueue  (Introduced in MSMQ 2.0 for the computer journal and dead-letter queues.)  
    DIRECT=URLAddressSpecification/QueueName  (Introduced in MSMQ 3.0)
    # where address can be TCP, SPX, OS, HTTP(S)
    #+end_src
    - encryption not supported
  + distribution list format names
  + multicast address format names: ~MULTICAST=<Address>:<Port>~
  + machine: ~MACHINE=computerGUID;JOURNAL/DEADLETTER/DEEADXACT~
  + connector: ~CONNECTOR=ForeignConnectorGUID[;XACTONLY]~

- queue handle: an open queue

- queue alias: an AD DS object

- ADs path

*** Navigation

- Lookup Identifiers: a locator of a message in a queue, like an index, used to read a specific message in the queue.
  + with this ID, an app can go directly to the message and navigate from that point.
  + there is another message ID, unique to that message, generated when the message is sent to
    identify the message itself, not to locate it in a queue.

*** Multiple Destinations

- *distribution lists*: public lists of destinations stored in Active Directory Domain Services
  containing references to public queues, queue aliases and other distribution lists
  + relying on directory service
  
- *Multiple-element format names*: private lists of destination queues of any number of single
  element format names, used only to send messages
  + A multiple-element format name is created by concatenating (separate by a comma) any number of public format names,
    private format names, direct format names, including direct format names for sending messages over HTTP/HTTPS,
    multicast address format names, and distribution list format names.

- *Multicast addresses*: a queue associated with a multicast address
